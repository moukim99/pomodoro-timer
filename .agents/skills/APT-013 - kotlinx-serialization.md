# kotlinx.serialization (APT-013)

## 1. الهوية
- **الاسم:** kotlinx.serialization
- **المعرّف المعماري:** `APT-013`
- **النوع:** library
- **الدور الأساسي:** مكتبة تحويل الكائنات وتسلسل/تفكيك البيانات (JSON / ProtoBuf) مبنية خصيصاً لـ Kotlin وقت البناء دون عبء الـ Reflection.

## 2. الموقع في المنظومة
- **النطاق المعماري:** Data & Networking
- **سير العمل:** يُعتمد ضمن سياق `03 - Data & Networking.md` لإدارة وتطوير طبقة (`commonMain`.).
- **معيار الاستخدام:**
  - **يُرشّح عندما:** تسلسل وفك تسلسل كائنات البيانات من وإلى JSON في استدعاءات الشبكة أو التخزين المحلي.
  - **يُستبعد عندما:** التطبيقات الخالية تماماً من تبادل أو تسلسل البيانات.

## 3. التوافق والاعتماديات
- **المتطلبات والبيئة:**
- طبقة التشغيل: `commonMain`.
- المنصات المدعومة: Android (✅), iOS (✅), macOS (✅), Windows (✅).
- مسار Android الصرف: المحول القياسي المعتمد مع Retrofit و DataStore.
- مسار KMP متعدد المنصات: المعيار الرسمي الموحد لتحويل بيانات JSON عبر المنصات الأربع بالتكامل مع Ktor و Room و DataStore.
- التوافق والتحقق: دعم رسمي ومستقر من JetBrains.
- **البدائل والتعارضات:** Moshi / Gson (حصرية لـ JVM ومستبعدة من KMP).
- **حدود المنصات:** تخضع للاستثناء الصارم للنطاق؛ بيئة Linux مستبعدة صراحةً، مع تركيز التوافق على خماسي (Android, iOS, macOS, Windows, Web).

## 5. تعليمات الاستخدام
- التزم بنطاق المسؤولية المحدد: مكتبة تحويل الكائنات وتسلسل/تفكيك البيانات (JSON / ProtoBuf) مبنية خصيصاً لـ Kotlin وقت البناء دون عبء الـ Reflection.
- في مسار KMP: راعِ حدود التجريد وضع الواجهات في `commonMain` وحصر التنفيذ في المنصات المستهدفة.
- في مسار Android: التزم بالأنماط المعتمدة في Jetpack ودورة حياة المكونات الرسمية.
- تكامل الأدوات: ارجع إلى كروت التقنية الموسعة في `antigravity/technology/` للحصول على إعدادات متقدمة ونماذج PoC عند الحاجة.
