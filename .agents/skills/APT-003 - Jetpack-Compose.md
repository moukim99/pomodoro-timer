# Jetpack Compose / Compose Multiplatform (APT-003)

## 1. الهوية
- **الاسم:** Jetpack Compose / Compose Multiplatform
- **المعرّف المعماري:** `APT-003`
- **النوع:** language
- **الدور الأساسي:** إطار عمل تصريحي حديث لبناء واجهات المستخدم الرسومية التفاعلية بلغة Kotlin.

## 2. الموقع في المنظومة
- **النطاق المعماري:** UI, State & Navigation
- **سير العمل:** يُعتمد ضمن سياق `02 - UI, State & Navigation.md` لإدارة وتطوير طبقة (`commonMain` في المشاريع متعددة المنصات، أو `androidMain` في مشاريع أندرويد الصرفة.).
- **معيار الاستخدام:**
  - **يُرشّح عندما:** المشروع يتطلب واجهة مستخدم رسومية تفاعلية.
  - **يُستبعد عندما:** التطبيقات الخالية من واجهة رسومية (أدوات سطر الأوامر أو الخدمات الخلفية).

## 3. التوافق والاعتماديات
- **المتطلبات والبيئة:**
- طبقة التشغيل: `commonMain` في المشاريع متعددة المنصات، أو `androidMain` في مشاريع أندرويد الصرفة.
- المنصات المدعومة: Android (✅), iOS (✅), macOS (✅), Windows (✅) — Linux خارج النطاق.
- مسار Android الصرف: الخيار الافتراضي الأصلي المعتمد لبناء واجهات أندرويد الحديثة عبر مكتبات `androidx.compose`.
- مسار KMP متعدد المنصات: يُعتمد **`Compose Multiplatform`** من JetBrains لكتابة الواجهات المشتركة من مصدر واحد لتعمل على الهواتف (Android و iOS) وأجهزة سطح المكتب (macOS و Windows).
- التوافق والتحقق: دعم رسمي ومستقر من Google على Android، ودعم رسمي من JetBrains على المنصات المتعددة (جاهز للإنتاج على Android و Desktop، ومستقر على iOS).
- **البدائل والتعارضات:** Native UI مستقل لكل منصة (SwiftUI / WinUI) عند الرغبة في عزل طبقة الواجهة تماماً.
- **حدود المنصات:** تخضع للاستثناء الصارم للنطاق؛ بيئة Linux مستبعدة صراحةً، مع تركيز التوافق على خماسي (Android, iOS, macOS, Windows, Web).
- **ملاحظة تصحيح (v2):** الهدف المكتبي (Windows/macOS) يعني Compose Desktop فوق JVM — انظر `APT-185` و`APT-191`؛ وموارد النصوص عبر `APT-190`.
